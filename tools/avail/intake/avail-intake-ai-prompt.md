# Промпт: сбор данных по продуктам в формат AVAIL intake

Вставьте текст ниже в ИИ-ассистента с доступом к интернету и файлам (Claude, Claude Code и т. п.).
Приложите: прайс-лист вендора (xlsx/pdf/csv) и пустой шаблон `avail-intake-template.xlsx`.
Подставьте вендора в первую строку.

---

Ты собираешь данные о продуктах вендора **<ВЕНДОР>** для библиотеки AV-проектирования AVAIL.
Результат — файл в формате приложенного шаблона `avail-intake-template.xlsx` (лист Products),
строго по правилам листа Instructions. Заполняй только данные карточки, порты не собираются.

## Шаг 1. Разбор прайс-листа
1. Прочитай приложенный прайс-лист. Для каждой позиции выпиши: артикул производителя, название
   модели, описание из прайса. Цены в форму не переноси: колонки цены в форме нет (репозиторий публичный).
2. Одна строка — один артикул. Варианты одной модели (цвет, MM/SM, регион, лицензия) — отдельные
   строки с одинаковой моделью и разным значением Variant.
3. Отбрось то, что не является оборудованием: услуги, гарантии, лицензии без железа, кабели
   на метраж. Перечисли отброшенное отдельным списком с причиной — не молча.

## Шаг 2. Данные производителя
Для каждого артикула найди **официальную страницу продукта у производителя** и, если есть,
**PDF-даташит / спецификацию**. Из них заполни:
- Model (как у производителя, с названием вендора), Short name, Description;
- Category, Device type — только значения из листа Lists;
- Input voltage, Power draw (W) или PoE draw (W), PoE budget (W), Heat (BTU/h);
- Height / Width / Depth (mm), Weight (kg) — переведи из дюймов/фунтов, округли до 0,1;
- Rack form (из Lists);
- для шасси — Slot families (chassis), для плат и вставок — Device type = expansion-card и
  Card for slot families;
- Reference URL (страница продукта), Datasheet URL (прямая ссылка на PDF);
- Source — откуда большая часть значений (из Lists).
- Lifecycle (из Lists) — Upcoming для анонсированного, но ещё не поставляемого продукта (в Lifecycle date —
  когда начнутся поставки: 2027-Q3), EoL — для снятого с производства; для остальных — пусто (Active).

## Правила
- **Ничего не выдумывай.** Если значения нет в документах производителя — оставь ячейку пустой
  и напиши в Note, чего нет и где искал. Оценки — только с Source = "AVAIL estimate" и пояснением.
  Для Upcoming значения по аналогу допустимы: в Note — «estimated from <модель-аналог>».
- Приоритет источников: даташит производителя > сайт производителя > ответ вендора > прайс-лист >
  сайт дистрибьютора. При расхождении бери более приоритетный и упомяни второе значение в Note.
- Числа без единиц измерения, десятичный разделитель — точка.
- PoE: если опубликован только класс — максимум класса (Class 1: 3.84, Class 2: 6.49,
  Class 3 / 802.3af: 12.95, Class 4 / 802.3at: 25.5) и пометка в Note.
- Габариты обязательны для всего, что может стоять в шкафу (стойка или полка); для акустики,
  микрофонов, настенных и настольных панелей, камер, дисплеев — по возможности.
- Не обходи защиту сайтов от ботов. Если сайт производителя недоступен для автоматического
  чтения — отметь это в Note («site blocks automated access») и переходи к следующему артикулу.
- Категория должна быть листом из Lists. Если подходящей нет — оставь пустой и напиши в Note,
  какую категорию предлагаешь.
- Вендор — только из списка Lists. Если вендора там нет, остановись и сообщи об этом.

## Результат
1. Файл `avail-intake-<vendor>-<yyyymmdd>.xlsx` по шаблону: примеры (серые строки) удалены,
   выпадающие списки сохранены.
2. Краткий отчёт:
   - сколько артикулов из прайса, сколько в таблице, сколько отброшено и почему;
   - сколько строк заполнено полностью; каких полей не хватает чаще всего;
   - список артикулов без страницы производителя или без даташита;
   - все места, где данные расходились между источниками.
